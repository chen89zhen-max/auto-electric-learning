# 群晖（Synology）部署与更新指南

适用项目：`auto-electric-learning`。仓库中的 `Dockerfile` 和 `docker-compose.yml` 已包含构建、端口、健康检查、日志轮转、数据持久化及目录权限修复配置。日常更新不应再到群晖手工编辑 Compose、创建 `data/backups` 或执行 `chown/chmod`。

## 一、当前固定配置

| 项目 | 配置 |
| --- | --- |
| 容器端口 | `3000` |
| 群晖端口 | `3001`，监听 `0.0.0.0` |
| 路由器映射 | 公网 `23000/TCP` → 群晖局域网 IP 的 `3001/TCP` |
| 数据 | 项目目录下 `./data` → `/app/data` |
| 备份 | 项目目录下 `./backups` → `/app/backups` |
| 应用身份 | UID/GID `10001:10001` |
| 更新策略 | `restart: unless-stopped`，构建成功后自动替换容器 |

外网访问地址为：

```text
http://你的公网IP或DDNS域名:23000
```

`3001` 是群晖上的 Docker 映射端口，`23000` 是路由器对外端口，两者不要混用。

## 二、首次部署

### Container Manager 图形界面

1. 打开 **Container Manager → 项目 → 新增**。
2. 项目名填写 `auto-electric-learning`。
3. 选择 Git 仓库并使用 `main` 分支：`https://github.com/chen89zhen-max/auto-electric-learning.git`。
4. 使用仓库自带的 `docker-compose.yml`，不要在群晖界面修改端口、卷或启动命令。
5. 当前已经部署成功的项目直接构建；只有全新空数据库才需要先按下一小节准备一次管理员密码。
6. 构建并等待容器状态变为 `运行中（健康）`。

镜像启动时会自动创建并修复 `data`、`backups` 的属主和权限，然后以非 root 身份运行数据库及 Web 服务。因此首次部署或以后重建都不再需要手工执行 `mkdir`、`chown`、`chmod`。

### 首个管理员密码

全新空数据库必须有 `ADMIN_INITIAL_PASSWORD` 才会初始化管理员。为避免把真实管理员密码提交到 Git，仓库只提供空的 `.env.production.example`，不会提交 `.env`。

- 当前已经运行成功的群晖项目：保留现有 `.env` 和 `data` 即可，以后更新无需再次设置。
- 全新换机或删除 `data` 后重装：仓库首次拉取完成后，通过 SSH 在项目目录执行 `cp .env.production.example .env`，再用 `vi .env` 填写 `ADMIN_INITIAL_PASSWORD`，然后回到 Container Manager 重新构建。这是唯一不能预置到公开代码仓库的本机配置。
- 已有数据库中存在管理员时，即使没有这个变量，应用也能正常重建和启动。

首次登录并完成强制改密、确认管理员已写入数据库后，可清空 `.env` 中的 `ADMIN_INITIAL_PASSWORD` 再重建；以后不再需要该初始密码。

若全新数据库缺少密码，容器会明确记录：

```text
ADMIN_INITIAL_PASSWORD is required when the database has no administrator
```

## 三、以后更新代码

平时只做下面三件事：

1. 把新版本推送到 GitHub 的 `main`。
2. 在 Container Manager 的项目页面执行“构建/重新构建”。
3. 等待容器显示 `运行中（健康）`。

不需要重新创建项目，不需要编辑 Compose，不需要重新设置端口，也不要删除 `data`、`backups` 或 `.env`。镜像和容器可以替换，SQLite 数据保留在宿主机卷中。

如果使用 SSH 更新，命令为：

```sh
cd /volume1/docker/auto-electric-learning
git pull --ff-only
docker compose up -d --build
docker compose ps
```

## 四、每次更新后的检查

先看 Container Manager 中的容器状态；健康检查最多需要约 1 分钟。日志应至少包含：

```text
[startup] persistent directories ready
[startup] database preflight passed
[vinext] Production server running at http://0.0.0.0:3000
```

再依次检查：

1. 局域网：`http://群晖局域网IP:3001/api/health`
2. 公网：`http://公网IP或DDNS域名:23000/api/health`
3. 管理员登录、一个学生账号登录及一条学习记录是否仍在。

健康接口应返回 `status: ok` 和 `database: ready`。

## 五、端口转发核对

路由器规则应为：

| 字段 | 值 |
| --- | --- |
| 协议 | IPv4 / TCP |
| 外部端口 | `23000` |
| 内部服务器 IP | 群晖的固定局域网 IP，例如 `192.168.1.99` |
| 内部端口 | `3001` |
| 状态 | 启用 |

同时在 DSM 防火墙中允许 TCP `3001`。若公网打不开，先用局域网地址测试 `3001`；局域网能开而公网不能开，问题就在路由器、运营商公网 IP/CGNAT 或 DSM 防火墙，不在容器。

## 六、备份

重大更新前执行一次一致性备份：

```sh
cd /volume1/docker/auto-electric-learning
docker compose --profile maintenance run --rm backup
```

备份服务固定以 UID/GID `10001:10001` 运行，文件写入 `./backups`。完整恢复流程见 [群晖 SQLite 备份与恢复操作规程](operations/SYNOLOGY_BACKUP_RESTORE.md)。

## 七、故障定位

| 现象 | 处理 |
| --- | --- |
| 容器反复重启 | 查看原始日志：`docker logs --tail 200 auto-electric-learning` |
| 日志提示 `/app/data` 或 `/app/backups` 权限错误 | 确认正在使用最新版镜像；新版入口会自动修复。不要再手改 Compose 的 `user` |
| 日志提示缺少管理员密码 | 仅全新空数据库会出现；恢复现有 `data`，或在本机 `.env` 一次性填写密码 |
| 群晖 `3001` 被占用 | 先停止占用端口的旧容器；不要直接把仓库配置改回 `3000`，否则路由器规则也要跟着改 |
| 容器健康但公网打不开 | 检查路由器 `23000 → 3001`、DSM 防火墙、公网 IP 和 CGNAT |
| 更新后数据为空 | 很可能换了项目路径或误删 `data`；停止写入并从备份恢复，不要继续创建新账号 |

## 八、调试阶段边界

当前采用公网 HTTP 端口直连，配置简单，但账号密码、会话和学习数据没有 HTTPS 传输保护，只适合当前调试和非真实数据。转入正式学生使用前，应改为 HTTPS 反向代理或 VPN，并关闭固定测试账号。
