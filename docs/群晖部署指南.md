# 群晖（Synology）部署指南

> 适用对象：本机 NAS 部署《汽车电工电子游戏》，供同专业教师小范围测试。
> 仓库：https://github.com/chen89zhen-max/auto-electric-learning.git（私有）
> 技术栈：vinext（Next.js 兼容）+ SQLite，容器化运行，Node 24。

---

## 一、部署架构说明

| 组件 | 说明 |
|------|------|
| 镜像 | Docker 多阶段构建（node:24-bookworm-slim），生产运行 standalone 产物 |
| 数据 | SQLite，持久化在 `./data` 目录，升级不丢数据 |
| 备份 | `./backups` 目录，compose 内置 maintenance 备份服务 |
| 端口 | 容器 3000，映射到 NAS 的 `${APP_PORT:-3000}` |
| 安全 | 容器只读、非 root 运行、健康检查、日志轮转，均已配置好 |

首次启动会自动建库并创建管理员账号（用户名/密码由环境变量指定），首次登录强制改密。演示测试账号在正式环境默认关闭（`ENABLE_DEMO_SEED=false`）。

---

## 二、准备 GitHub 访问令牌（PAT，仅私有仓库需要）

> **仓库已设为公开时，本节整体跳过**——NAS 直接匿名 clone/pull，不需要任何凭据。

仓库保持私有时，NAS 拉取代码需要令牌：

1. 登录 GitHub → 右上角头像 → **Settings** → 左栏最底 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. 填写：
   - Token name：`synology-pull`（随意）
   - Expiration：建议 90 天（到期需重新生成并更新 NAS 上的地址）
   - Repository access：**Only select repositories** → 选 `auto-electric-learning`
   - Permissions → Repository permissions → **Contents** → `Read-only`（其余不授权）
3. 生成后**立即复制**令牌（形如 `github_pat_xxxx...`，只显示一次）

## 三、方式一：图形界面部署（Container Manager，**本项目不推荐**）

> **不推荐本项目使用此方式**。本仓库的 `docker-compose.yml` 用了 `${ADMIN_INITIAL_PASSWORD:?...}` 强制必填语法，而 Container Manager 从 Git 源 clone 时不会生成 .env，会在解析阶段直接报 `error while interpolating`，整个项目无法启动。**请直接走方式二（SSH + docker-compose）**。

### 如果仍想用图形界面（需要删项目重建）

1. 删掉失败的项目
2. 重新创建项目，**在 compose 编辑界面把 `ADMIN_INITIAL_PASSWORD` 和 `BIND_ADDRESS` 写死**（不要用 `${}`），端口映射也写死为 `0.0.0.0:3000:3000`
3. 后续每次改代码 push 后，要回到项目页手动点"构建"

> 但这种方式对后续迭代不友好——compose 在仓库里、环境变量在你本地，**配置与代码不同步**。强烈建议改走方式二。

适合不熟悉 SSH 的场景，全程 DSM 网页操作。

### 步骤 1：创建项目

1. DSM 打开 **Container Manager**（套件中心确认已安装）
2. 左侧选 **项目** → 点 **新建**
3. 常规设置：
   - 项目名称：`auto-electric-learning`
   - 路径：`/volume1/docker/auto-electric-learning`（DSM 会自动创建）
4. 来源选择 **从代码存储库**（Git），填写：
   - 存储库 URL：`https://github.com/chen89zhen-max/auto-electric-learning.git`
   - 分支：`main`
   - （私有仓库时需在 URL 中嵌入凭据：`https://chen89zhen-max:你的PAT令牌@github.com/chen89zhen-max/auto-electric-learning.git`）
5. 点击**下一步**，DSM 会读取 docker-compose.yml 并显示编辑界面

### 步骤 2：编辑 compose（关键）

在 DSM 显示的 compose 内容中，把 `environment` 部分的变量替换为实际值：

```yaml
    environment:
      NODE_ENV: production
      APP_DATA_DIR: /app/data
      DB_MIGRATIONS_DIR: /app/migrations
      HOST: 0.0.0.0
      PORT: 3000
      ENABLE_DEMO_SEED: "false"
      ADMIN_INITIAL_USERNAME: admin
      ADMIN_INITIAL_PASSWORD: "换成你的强密码"      # 必填，首次建库的管理员密码
      TZ: Asia/Shanghai
```

同时把端口映射改为对局域网开放（compose 中默认 `127.0.0.1` 只允许 NAS 本机访问）：

```yaml
    ports:
      - "0.0.0.0:3000:3000"
```

### 步骤 3：构建并启动

1. 点击**完成**，DSM 开始 clone 代码并构建镜像
2. **首次构建约 5～20 分钟**（取决于 NAS 型号与网络），可在项目页查看日志
3. 状态变为"正在运行"即成功

### 步骤 4：验证

- NAS 本机浏览器打开 `http://localhost:3000`
- 电脑（同局域网）浏览器打开 `http://NAS的IP:3000`，出现登录页即部署成功
- 用 `admin` + 你设置的初始密码登录，系统会强制改密

## 四、方式二：SSH 命令行部署（推荐迭代更新）

适合后续快速迭代：改代码 → push GitHub → NAS 拉取重建，全程约 2～5 分钟。

### 前提

1. DSM **控制面板 → 终端机和 SNMP → 启用 SSH 功能**
2. 电脑上用终端连接：`ssh 你的管理员用户名@NAS的IP`，输入密码后 `sudo -i` 提权

### 首次部署

```bash
```bash
mkdir -p /volume1/docker/auto-electric-learning
cd /volume1/docker/auto-electric-learning
git clone https://github.com/chen89zhen-max/auto-electric-learning.git repo
# 私有仓库时才需要带令牌：
# git clone https://chen89zhen-max:你的PAT令牌@github.com/chen89zhen-max/auto-electric-learning.git repo
cd repo

# 准备环境变量文件
cp .env.production.example .env
vi .env
```

编辑 `.env` 内容：

```ini
# 局域网教师直接访问，改为 0.0.0.0（默认 127.0.0.1 只有 NAS 本机能访问）
BIND_ADDRESS=0.0.0.0
APP_PORT=3000
TZ=Asia/Shanghai
ENABLE_DEMO_SEED=false
ADMIN_INITIAL_USERNAME=admin
ADMIN_INITIAL_PASSWORD=换成你的强密码
```

启动：

```bash
docker-compose up -d --build
# 首次约 5～20 分钟；完成后再执行一次确认状态
docker-compose ps          # 应显示 running (healthy)
docker logs -f auto-electric-learning   # 看启动日志，Ctrl+C 退出
```

### 日常迭代更新（每次改完代码 push 之后）

```bash
cd /volume1/docker/auto-electric-learning/repo
git pull
docker-compose up -d --build   # 增量构建，通常 2～5 分钟
```

数据存放在仓库外的 `../data`（即 `/volume1/docker/auto-electric-learning/data`，按 compose 相对路径 `./data` 解析），**更新代码不会丢数据**。

## 五、教师测试的组织

1. 管理员登录后，在**系统管理**中为每位测试教师创建教师账号（不要分发 admin 账号）
2. 教师访问地址：`http://NAS的IP:3000`（校园网/同一 Wi-Fi 内，电脑、手机、平板浏览器均可）
3. 建议 NAS 设置固定局域网 IP（控制面板 → 网络 → 网络接口 → 编辑 → 手动设置网络配置），避免 DHCP 换 IP 后地址失效
4. **首次部署后请到 Container Manager 界面把之前那个"无法构建"的项目删掉**（避免后续误操作）

### 全通关人工测试账号（student_pass）

系统内置一个**默认通关全部任务**的学生账号，专供教师人工测试任意关卡：

| 项目 | 值 |
|------|-----|
| 账号 | `student_pass` |
| 密码 | `Student#2026` |
| 登录页 | 有"⚡ 一键填入全通关测试学员"按钮，点击自动填入 |

说明：

- 该账号**每次容器重启/更新部署后自动恢复全通关进度**，随时可以进入任意关卡体验
- 它不属于任何真实班级，不会出现在教师的学情大屏里，不干扰真实学生数据
- 该账号默认开启；如在 `.env` 中设置 `ENABLE_TEST_PASS_ACCOUNT=false` 则完全不创建（重启容器后生效）

## 六、数据备份与恢复

```bash
cd /volume1/docker/auto-electric-learning/repo

# 手动备份（备份到 ../backups，带时间戳）
docker-compose --profile maintenance run --rm backup

# 查看备份文件
ls -lh ../backups/
```

恢复使用 `npm run db:restore` 对应的 `scripts/restore-sqlite.mjs` 脚本（详见脚本内说明）。

**重大版本更新前，务必先执行一次备份。**

## 七、安全注意事项

1. **不要把 3000 端口直接暴露到公网**（路由器不要做 3000 端口映射）
2. 校外确需访问时，优先使用群晖 VPN（如 WireGuard 套件）或 DSM 自带反向代理 + HTTPS：
   - 控制面板 → 登录门户 → 高级 → 反向代理，来源随意端口/HTTPS，目标 `localhost:3000`（此时 `.env` 保持 `BIND_ADDRESS=127.0.0.1`）
3. PAT 令牌只授予该仓库只读权限，泄露风险可控；到期后重新生成并更新 NAS 上的 clone 地址（`git remote set-url origin 新地址`）。仓库设为公开后 PAT 不再需要，建议到 GitHub 删除该令牌
4. 学生/教师数据属敏感信息，`data` 目录不要放入任何网盘共享或备份上云

## 八、常见问题

| 现象 | 处理 |
|------|------|
| **构建报错 `Get "https://registry-1.docker.io/v2/": proxyconnect tcp: dial tcp 127.0.0.1:7890: connect: connection refused`** | 这是**国内群晖拉不到 Docker Hub 镜像**。先检查 **DSM → 控制面板 → 网络 → 代理** 是否被误设成 `127.0.0.1:7890`（那是你电脑的端口，群晖本机 7890 没东西），有则改为你电脑的 LAN IP（如 `192.168.0.241:7890`）或临时关掉。然后到 **Container Manager → 设置 → 镜像 → 镜像加速器** 加至少一个国内源（推荐 `https://docker.m.daocloud.io`），保存后回到项目页重新点"构建" |
| 首次构建失败 `npm ci` 超时 | 群晖访问 npm 慢或不稳。改 `Dockerfile` builder 阶段加一行 `RUN npm config set registry https://registry.npmmirror.com`，重新 push 与构建 |
| 教师无法访问 | 确认手机/电脑与 NAS 同一网段；检查 DSM 防火墙（安全性→防火墙）未拦截 3000；确认 `.env` 里 `BIND_ADDRESS=0.0.0.0` |
| 忘记 admin 密码 | 删除 `../data` 目录重启等于重置全部数据（慎用）；或让其他管理员在后台重置 |
| 升级后启动失败 | `docker logs auto-electric-learning` 查看报错；必要时 `git checkout` 回上一版本重新构建 |
| 磁盘空间 | `docker system prune` 清理无Tag镜像；构建缓存多了会占几个 GB |
| 解析阶段就报 `error while interpolating` | compose 中的 `${ADMIN_INITIAL_PASSWORD:?...}` 找不到值。说明走 Container Manager 图形方式部署时不会自动创建 .env。改走方式二（SSH），或重建项目时把变量写死 |
