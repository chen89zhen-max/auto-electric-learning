# 给 Antigravity / Gemini 的分阶段执行任务书

版本1.0；完成日期2026-09-06。先阅读同目录《01-总体优化设计》《02-教材目标与关卡覆盖矩阵》。

## 一、执行约定

目标是把现有项目逐步改造成可用于课堂的汽车电工电子互动游戏。保留已验证的认证、班级、权限与存储功能。当前已有0—2关；不要从零重建，不把课程改为教材翻页或选择题闯关，不一次性生成全课程空壳。

总设计文档是拟实施基线，不是已实现清单。每次只执行用户指定的一个阶段。完成后提交交接包，由用户通知Codex复验；有阻断问题时先修本阶段，复验通过再进入下一阶段。需要改变目标、先修、模型边界或评价规则时提交具体变更说明，不自行用“优化”替换课程决策。

现有工作区有未提交、已暂存和未跟踪文件。先检查并记录，不得`reset --hard`、清理未跟踪文件、覆盖其他开发者改动或把真实数据库提交到仓库。阶段提交只纳入已核对的本阶段文件，不用`git add .`混入扫描件、账号数据、临时目录和个人配置。

## 二、阶段及验收门

### P0：冻结基线，修正安全教学和文案

目的：先消除错误学习暗示，保住可用版本。

范围：`src/levels/level01/`、安全规则与相关测试；大厅认证文案；README/TODO/KNOWN_ISSUES状态核对。不改数据库架构，不开发新关。

必须交付：

1. 记录当前提交、工作区差异、运行环境和测试基线；在隔离测试库操作。
2. 重构`ShockSimulationLab`：不以接触带电导体、同时接触两相、脱下防护为完成条件；改为案例风险识别、抽象模型观察和安全决策。
3. 删除“穿鞋/垫/手套所以绝对0电流安全”等现实保证；禁止同类错误从提示、动画字幕、完成反馈重新出现。
4. 区分急停与隔离确认；急救/火情采用有复核状态的配置。未审定模块可教师预览，但不得标为正式可用。主线安全前置仅凭经审定的准入目标开放；未审定应急片段不自动计为学过。
5. 大厅改“游戏任务完成/成长称号”，删除资格认证和无依据的教学标准符合声明。
6. 旧报告保留历史日期，不把旧问题清单直接当当前事实；建立一份当前状态清单。

退出标准：普通学习路径没有任何必须实施危险动作才能前进的条件；危险请求不改变执行状态；三角色、退出和已有进度保存不回归；安全专业复核未完成项被明确限制发布。不能以自动化全绿代替专业审定。

### P1：统一课程注册、尝试记录和证据框架

目的：支持新的路线和复练，避免后续逐关返工。

范围：课程注册表；`src/types/progress.ts`、进度store、服务端学习状态/事件与数据库迁移、课程大厅、教师证据页。复用现有账号和授权链。

必须交付：稳定关卡ID、能力依赖、发布状态；前后端共享注册数据；attempt与汇总分离；本账号待同步和恢复机制；六维证据状态；版本绑定；LEVEL_00—02兼容映射及回滚。先接入现有关和最小样例，后续内容标建设中。

复练规则：同一关允许新的attempt；同一attempt重复提交幂等；首次、最近、最佳独立、迁移记录分开。旧成绩和教师评价不删除、不改解释。

退出标准：换账号不串数据；刷新可续做；重复提交只有一份结果；同ID不同事件内容被拒绝或明确报冲突；新版本不静默改旧结果；建设中关卡不能通过URL/API进入；移除某教师任教后立即失去访问；教师演示不写学生达成。

### P2：完成基础测量样板（A02—A04）

目的：验证一套真正可复用的仪表与直流模型。

范围：拓扑/数值求解、仪表模型、受控故障配置；A02电压、A03电阻、A04电流；A01必要适配。保留已有图分析能力，去掉固定LEVEL_02组件初始化对通用引擎的依赖。

按A02→A03→A04实现。A03脚本见总体设计第6节。各关均有跟练、独立、迁移模式，至少一条非危险错误路径、一条危险拦截路径、一个参数变式。模拟表与钳形表作为数字表之后的短任务，不与首轮入门同时出现。

退出标准：同一状态得同一结果；表笔测点互换有合理符号变化；改电路参数读数同步变化；OL、悬空、短路、保险熔断和模型失败不混为0；工具能力不支持时不能生成假读数；学生靠测量与判断完成，不是点固定答案。

### P3：完成直流规律与设计（B01—B06）

目的：让学生从会测发展到会预测、解释和设计。

顺序：控制变量与欧姆关系→串并联→节点/回路→功率电能→电源内阻→分压与传感器。每关拆2—4个短片段，保留教材计算与数据解释目标。

必须演示的反例：串并联不是看元件排布；换参考点不改变两点电压；并联增加负载会改变总电流；额定功率不是所有工况实际功率；分压器加负载后输出变化；空载电源电压正常不能证明带载正常。

退出标准：各关有正常、错误、变式的模型算例；图、表、动画和公式对同一状态一致；计算器可用但不能替代正确接线；不给尚未学的电子器件强行设必修前置。

### P4：完成直流诊断闭环并组织首次试教（C01—C03）

目的：验证产品能训练证据化诊断。

复用总体设计C01样例；C02开放断路、高阻、短路三类故障。初学固定单故障，独立练习按可诊断题库换种子，多故障暂不进入必修。

允许多种正确测量顺序；不能把“唯一正确点击顺序”当排故策略。题库每个种子保存故障真值、支持的工具、可区分假设的测点及预期模型范围。学生看不到真值，审查者可重演。

教师端增加班级任务、卡点、证据查看和补练；按总设计落地共同授课“已发布评价共享、草稿私有、本人修订留痕”。权限检查在服务端完成。

退出标准：修复前后测量闭环；猜中零件但无证据不得独立通过；危险跨接被拒；有效的替代测量路线通过；新种子仍能求解且可诊断；完成3—5人零说明试玩，记录实际问题并修复。此阶段形成可小范围试教的直流课程版本。

### P5：电磁、交流与电机（D01—D05）

开始前完整阅读对应教材任务11—14及19，补目标卡页码、图号和模型范围。不要仅凭任务标题直接生成细节。

开发继电器控制/负载分离、受力与直流电机、交流感应与波形、自感互感、变压器受控模型。教学上分多次课堂；任务13的结构、交流基础和传感器目标不得只用发电动画替代，传感器在P6的E06闭环。

退出标准：正反转、稳态/瞬态、频率/幅值、匝数比等受控变量结果可解释；任务19选学属性可配置；不让学生进入实际高压端接线操作；检查真实车型情境与通用训练台模型的区别。

### P6：电子器件、信号与装配（E01—E07）

开始前完整阅读任务10、15—18以及13的传感器部分。分子包执行，每个子包独立提交证据：E01/E02器件与储能；E03整流滤波；E04/E05控制与逻辑；E06传感器；E07装配与工艺。

退出标准：二极管正反向、充放电、整流滤波、三极管三态、与或非输入组合均有数值/逻辑依据；焊接的虚拟工艺与教师实物评价分开；器件检测不通过看外观猜答案；模型不支持的工况明确拒绝，不静默返回固定值。

### P7：综合交付和学校发布验收

F01只组合学生已掌握的模块。首版用低压教学控制板或灯光控制工单，不做任意整车故障仿真。可选情境：灯光控制板装配后异常、继电器控制灯组异常；每种题有证据链和功能验收表。

完成一班试教；40名学生同时进行常见动作和结算的压测；群晖Docker实机、HTTPS和数据卷备份恢复；学校浏览器和触控设备验收。个人身份、授权、数据保留等按学校既定规则落实，不在此另造泛化审批流程。

退出标准：技术、教学、部署三项分别通过；无阻断项；每个必修教材目标有已实现关卡和证据（不要求同名同序）；选学和未覆盖目标明确；能从备份恢复并核对学习记录；发布与回滚有可执行步骤。

## 三、跨阶段基准用例

以下为教学模型算例，不是所有汽车设备的真实参数。数值输出先验证未舍入值；展示再按仪表分辨率处理。直流基准采用理想源、理想导线和指定电阻，数值容差绝对1e-6或相对1e-5取较宽者。

| 编号 | 输入与操作 | 预期结果 |
|---|---|---|
| V01 | 12V串联6Ω、6Ω | I=1A；各压降6V；总功率12W |
| V02 | 12V并联6Ω、6Ω | 各2A，总4A；等效3Ω；断一支另支仍2A |
| V03 | 电压表笔从正负接法交换 | 读数从+12V变为−12V，不能报接线故障 |
| V04 | 220Ω±5%，实测224Ω或240Ω | 分别在/不在209—231Ω区间；单位变更后结论不变 |
| V05 | 在带电网络使用Ω挡 | 动作拒绝，原因可读，无虚构测阻结果 |
| V06 | 电流挡直接跨接电源 | 执行前拒绝；不能为了演示熔断而实际推进危险操作状态 |
| V07 | 12V源，内阻1Ω，负载5Ω | I=2A，端电压10V，内压降2V；开路端电压12V |
| V08 | 12V；6Ω灯＋0.5Ω供电接点＋0.1Ω搭铁 | I≈1.818181818A；灯压≈10.909090909V；两侧压降和灯压相加12V |
| V09 | 12V分压，上下各1kΩ；给下支并接1kΩ负载 | 空载输出6V，带载输出4V；不能仍显示6V |
| V10 | 12V、1000Ω、1000μF充电，初始0V | 解析模型τ=1s，t=1s时约7.585446706V；改变C改变时间过程 |
| V11 | 两输入与门 | 00、01、10为0，11为1；不只测试11 |
| V12 | 同一配置与种子重开 | 故障与物理结果一致；新attempt独立记录；不因换账号重用上个人结果 |

P5/P6必须补各模型的独立算例；不能仅用与实现同一段算法生成“预期值”。边界测试包括空网络、悬空节点、非法端子、模型不支持、求解失败、存储故障和会话失效。

## 四、每阶段提交的交接包

放入`docs/handoffs/P阶段号-日期/`，提交一份`HANDOFF.md`及相关证据，内容必须包含：

1. 实施阶段、起止版本/提交、改动文件和数据库迁移；工作区中未纳入阶段的变更说明。
2. 已实现的目标ID和关卡ID、未实现项与具体原因；不可写“基本完成”。
3. 正常路径、错误路径、迁移路径的操作说明和截图/短录屏；仿真固定种子与重演步骤。
4. 本次实际执行的测试命令、结果、时间、日志位置；区分自动化、人工浏览器、实机和专业内容复核。
5. 已知问题，按“安全或数据阻断／教学阻断／体验改进”标级；可复现步骤、预期与实际。
6. 当前启动方式、测试入口和测试账号取得方式；不在文档写真实密码或生产密钥。
7. 回滚与恢复步骤；是否需要用户做专业审定、提供学校设备或组织学生。

每次改动运行与之相关的测试；阶段结束执行项目现有`npm test`、`npm run typecheck`、`npm run lint`、`npm run build`，报告真实结果。数据库测试必须指向隔离测试库。涉及交互应人工走至少一个正常和一个错误路径；不得以构建通过代表可玩。

## 五、总设计师复验清单

Codex复验先读交接包、变更范围和实际代码，再做有针对性的运行检查。优先查五件事：是否教错、是否真交互、是否能迁移、是否留证据、是否破坏既有账号和进度。收到文字“已完成”不能直接照收。

结论只用：通过；有条件通过（列明适用范围）；不通过（列出阻断及修复证据）。教学内容审定、学生实测和群晖实机若未做，明确未验，不能用模型推理补签。

用户确认的协作方式：**Gemini每完成一个阶段，用户在本任务中通知Codex检查。无自动定时巡检。** 默认由Gemini按问题单修复，Codex复验；需要Codex直接修补时先明确同一文件当前由谁负责，避免并行覆盖。
