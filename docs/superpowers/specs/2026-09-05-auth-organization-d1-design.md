# 汽车电工电子游戏账号、教学组织与 D1 整改设计

日期：2026-09-05  
状态：已获用户批准，采用方案 A  
依据：`汽车电工电子游戏_二阶段修改后账号与教学组织复验报告_2026-09-05.md`

## 1. 整改目标

本次整改不开发 Sprint 3，也不重写 Sprint 0—2 的游戏内容。目标是把现有“可以演示”的账号和教学组织能力提升为可正式部署、可审计、可按班级隔离的基础平台，并通过复验报告中的 15 项验收用例。

整改坚持以下边界：

1. 学生是学习者，只有学生形成正式学习进度、学习尝试和成绩。
2. 教师是教学组织者，只能访问当前任教班级；不得整体覆盖学生原始游戏进度。
3. 系统管理员是账号与组织治理者，不进入学生课程大厅，不形成学习进度。
4. 服务端身份、账号状态、任教关系和当前归班关系是唯一可信依据。
5. 生产数据统一保存到 Sites/Cloudflare D1；本地文件数据库只保留为明确的测试工具，不进入生产代码路径。

## 2. 总体架构

系统按四层组织：

- 界面层：学生学习端、教师工作台、系统管理员后台互相独立。
- API 层：认证、学生学习、教师教学、系统管理按资源拆分。
- 业务服务层：集中实现授权策略、账号生命周期、教学组织关系、学习状态迁移和审计。
- 持久化层：生产使用 D1，所有查询使用参数化 prepared statement，多步骤写入使用 D1 batch；迁移文件只追加、不运行时建表。

现有 `SafetyRuleEngine`、Sprint 0—2 状态机和游戏组件保持独立。账号整改只改变它们读取身份、加载进度和提交学习结果的方式。

## 3. 身份与账号状态

### 3.1 角色

- `student`：学生登录/激活、学习本人课程、查看本人报告。
- `teacher`：教师登录、查看任教班级、评价学生、受控发起重训。
- `admin`：独立系统管理登录、管理账号与组织、查看审计。

登录请求必须携带 `expectedRole`。服务端验证实际角色是否匹配入口，但失败信息统一为“账号、密码或登录入口不匹配”，不泄露账号真实角色。

### 3.2 账号状态

统一状态为：

- `pending_activation`：管理员已创建，等待学生首次激活。
- `active`：正常使用。
- `suspended`：管理员停用，所有会话立即失效。
- `locked`：安全策略锁定，不允许登录。
- `deleted`：软注销，只保留历史和审计，不允许登录。

`must_change_password=1` 时，用户登录后只能访问 `/api/auth/me`、`/api/auth/change-password` 和退出接口。改密成功后清除标志并撤销除当前新会话以外的旧会话。

## 4. 会话与前端身份

1. HttpOnly Cookie 和服务端 `sessions` 表继续保留。
2. 应用启动先调用 `GET /api/auth/me`，未完成前不根据 localStorage 渲染角色页面。
3. localStorage 不再保存可信角色和完整用户资料，只允许保存非敏感界面偏好。
4. 退出调用 `POST /api/auth/logout`。无论网络成功与否都清理前端状态；服务端失败时明确提示风险。
5. 统一请求封装处理 401 和 403：401 清理前端身份并回到对应入口；403 保留身份并显示权限不足。
6. 账号停用、锁定、密码重置或管理员强制下线时撤销该用户全部有效会话。

## 5. D1 数据设计

### 5.1 保留表

保留并迁移：`users`、`sessions`、`user_progress`、`login_attempts`、`audit_logs`、`classes`、`teacher_class`、`student_class`、`course_versions`、`learning_attempts`、`learning_events`。

### 5.2 新增表

- `student_activations`：学生 ID、激活码哈希、失效时间、使用时间、创建人。
- `teacher_evaluations`：教师、学生、学习尝试、评价内容、成绩、创建及更新时间。
- `progress_corrections`：受控重训/纠错申请、原因、操作者、审批或执行结果。

### 5.3 约束

- 用户名全局唯一。
- 同一学生最多一条 `is_current=1` 的归班关系。
- 同一教师、班级、课程最多一条有效任教关系。
- 关系写入前必须校验用户角色、用户状态、班级状态和学校范围。
- `student_class` 是当前班级唯一事实源；`users.class_name` 仅在过渡期作为只读展示缓存，后续移除。
- `user_progress`、`learning_attempts` 只允许学生拥有。迁移时清理教师和管理员的脏进度记录。

### 5.4 迁移策略

在 `db/schema.ts` 定义 D1 Schema，生成并保存不可变迁移文件。迁移按以下顺序执行：

1. 建立新状态、激活、评价、纠错及唯一索引。
2. 根据已有合法 `student_class` 修复展示字段；对无归班学生标记待管理员处理，不再按自由文本自动猜班。
3. 清理教师、管理员的 `user_progress`。
4. 删除或停用重复测试身份；生产环境不运行演示种子。

迁移和数据回填分开，迁移文件不包含演示数据或大批量业务数据。

## 6. API 设计

### 6.1 认证 API

- `POST /api/auth/login`：账号、密码、`expectedRole`。
- `POST /api/auth/logout`：撤销当前会话并清 Cookie。
- `GET /api/auth/me`：返回服务端当前身份；只有学生返回学生进度摘要。
- `POST /api/auth/change-password`：校验旧密码/临时凭证并完成强制改密。
- `POST /api/auth/activate`：学生使用学号和一次性激活码设置初始密码，班级来自管理员预置关系。

旧 `/api/auth` 在过渡期只做兼容转发，完成界面切换后移除注册动作。

### 6.2 学生学习 API

禁止客户端上传整份 `UserProgressData`。改为提交幂等学习事件：

- `POST /api/learning/events`
- 输入：`eventId`、`levelId`、`eventType`、必要证据和客户端时间。
- 服务端依据当前尝试、前置关卡和允许的状态迁移校验。
- 合法事件写入 `learning_events`，同步更新学习尝试和进度投影。
- 不接受请求体中的用户名作为进度所有者，所有权来自当前 Session。

### 6.3 教师 API

- 任教班级和学生名单只从当前任教关系派生。
- 教师评价写入 `teacher_evaluations`，不修改游戏原始成绩。
- 如需重训，仅允许对任教班级学生的单次尝试执行专用重训操作，必须填写原因并审计；不得上传整份进度。
- 导出严格按任教关系过滤并记录字段范围和导出行数。

### 6.4 管理员 API

- `/api/admin/users`
- `/api/admin/classes`
- `/api/admin/teacher-classes`
- `/api/admin/student-classes`
- `/api/admin/audit-logs`

每个资源支持报告要求的创建、编辑、停用、恢复、软注销、归档、分配、撤销、转班和历史查询。所有状态变化由服务端授权策略控制并写审计。

## 7. 界面与导航

登录首页提供三个明确入口：学生登录/激活、教师登录、系统管理登录。

- 学生登录成功：进入课程大厅，加载本人进度。
- 教师登录成功：直接进入 `TeacherDashboard`；课程预览使用独立预览上下文，不产生学习记录。
- 管理员登录成功：直接进入 `SystemAdminConsole`；不显示技师等级、课程进度、演示模式或重置学习记录。
- 强制改密用户：无条件进入改密页。

系统管理员后台包含用户、班级、任教关系、学生归班、账号安全和审计六个区域。教师工作台只包含任教班级、学生学情、过程证据、评价、受控重训和最小化导出。

## 8. 错误与审计

- 401：未登录或会话失效。
- 403：已登录但角色、任教或组织范围不允许。
- 409：用户名、有效任教关系、当前归班关系等唯一性冲突。
- 422：状态迁移、账号状态或对象角色不合法。

关键拒绝行为同样写入审计，包括错误入口登录、跨班读取/写入、非法关系分配、强制改密绕过和生产初始化尝试。

## 9. 测试与验收

采用测试驱动实施，每项修复先写失败测试，再实现最小修复。测试分为：

1. 单元测试：授权策略、账号状态、学习状态迁移、关系校验。
2. API 集成测试：三角色入口、退出、强制改密、CRUD、转班、跨班拒绝和统计一致性。
3. D1 集成测试：迁移、唯一约束、批处理、并发和无本地文件依赖。
4. 浏览器 E2E：复验报告列出的三角色完整流程。
5. 运行验收：40名学生并发写入、备份恢复、迁移失败回滚或前滚恢复。

每个实施包完成后运行相关测试；全部完成后统一运行测试、类型检查、代码规范、生产构建和浏览器验收。

## 10. 实施顺序

1. P0 安全封堵：真实退出、禁止教师/管理员写原始进度、角色匹配、取消自由注册、生产种子隔离。
2. D1 切换：Schema、迁移、异步持久化服务、现有数据回填策略。
3. 账号与组织领域：账号状态、激活、关系约束、审计原子性。
4. 管理员后台和资源 API。
5. 教师工作台和评价/重训流程。
6. 学生事件化进度与旧接口退役。
7. E2E、并发、备份恢复、迁移演练和整体复验。

在上述工作完成并验收前，不开始 Sprint 3。
